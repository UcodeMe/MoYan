# 简介

Touch UI 是一套响应式 UI 框架，适用于网页前台开发、web 应用前台开发、触屏 app 前台开发，尤其对于多终端兼容的界面开发，具备极大的优势。

## 特性

与其他的 UI 框架相比，Touch UI 具备以下特性：

* UI 库跨终端；
* 响应规则的方式处理各终端差异，极大降低多端兼容的难度；
* 矢量化，更智能地适配各种屏幕比例；
* 配色方案可在限定制，定制意味着我们可以无限地扩展 UI 库；
* 服务端（Java）与客户端（JS）双引擎设计；
* 支持多语言；
* 自定义点击事件。

当然，以上特性只是在 IE10+ 的浏览器上才支持的，如果您的用户不幸活在古代，我们也可以支持 IE8，只是特性，就算了吧，能看已经不错了（严肃脸.jpg）。


## 响应规则

响应规则是 Touch UI 特有的祖传手艺，是目前已知的实现多屏兼容的最简单粗暴的方法，使用者只需要知道样式名及其在手机终端对应的状态即可。

例：以下是一个表单的 HTML，样式 ``c_form`` 规定它是一个表单，``c_form-col-3`` 是一句样式类，表示这个表单将以 3 列的形式呈现，**``c_form-phone-col-1`` 则是响应规则，它规定这个表单在手机上以 1 列的形式呈现。**（<a href="#/example/component/form-phone-col" target="_blank">查看演示</a>）

```html
<div class="c_form c_form-col-3 c_form-phone-col-1">
	...
</div>
```

例：以下是一个分列布局的 HTML，**``l_col-phone-split-3`` 是响应规则，它规定这个分列的布局，在手机上以递进的形式呈现，**``l_col-cur-1`` 表示默认显示第一列，我们通过 JS 控制 ``l_col-cur-1``，便可以实现层进的动作。（<a href="#/example/layout/col-phone-split" target="_blank">查看演示</a>）

```html
<div class="l_col l_col-phone-split-3 l_col-cur-1">
	<div class="l_colContent">
		<div class="l_colItem">
			...
		</div>
		<div class="l_colItem">
			...
		</div>
		<div class="l_colItem">
			...
		</div>
	</div>
</div>
```

## 矢量化

Touch UI 矢量化分三个层次：资源矢量、控件矢量、界面矢量。

**资源矢量**

整个框架绝大部分都是使用的 CSS 与 iconfont 构成，这样一来无论控件如何缩放，都不会失真。

**控件矢量**

任何一个 UI 元素都可以通过 font-size 的设置来等比伸缩为任意大小，如下代码可将 card 组件缩放至默认大小的 1.39 倍：

```html
<div class="c_card" style="font-size:139%">
	...
</div>
```

**界面矢量**

界面的整体比例，会自动根据屏宽来等比伸缩。

这样一来，我们无需关心屏幕的 DPI 与 PPI。

而且，Touch UI 是基于 JS 去即时监听的 top 对象的宽度，这将意味着，与传统的 vw 模式相比，Touch UI 可有效地支持 ``<iframe>``，同时如果需要其他的细微调整，也可以更灵活地处理。

**直接控制一下本站的窗口大小即可看到效果噢**



## 定制化

定制化与 bootstrap 的定制功能有些类似，用户可以自行选择需要哪些控件，以有效减轻框架资源的大小，做到各取所需。

另一个方面来讲，这使得 Touch UI 可以无限地去扩展自身的 UI 库，为大家提供更丰富的 UI 控件。

此外，与 bootstrap 不同的是：

1. 对于色彩风格的定制，只需要确定自己六大色调即可，不需要一个个子项逐个去设置。
2. 不久的将来，将支持控件紧密程度的定制。

## 双引擎设计

基于 Nodejs 的 Reactjs、Angularjs、Vuejs 的前端框架均支持在客户端与服务端运行，但它们的组件封装均是基于 JS 的，需要专业的前端人员去处理。

而 Touch UI 一开始便是基于 Tapestry 框架进行的组件封装，能更好地融入 Java 开发环境，在服务端将解析好的页面返回给客户端，适合 Java 开发为主力的团队使用。

同时，面向未来的 Touch UI 也提供了本地可解析的引擎 Touch JWC，它支持使用 JS 进行组件解析，更适合前后端分离的开发团队。

无论是基于 Tapestry 的组件封装，还是 Touch JWC 的组件封装，组件的使用方式都是一致的，除开数据源，其他部分均可支持两种模式的快速切换。

## 国际化支持

对于多国语言的产品，往往需要根据工程的不同或者产品使用者的诉求不同，可切换至自己需要的语言。

基于 Touch UI 的 web 应用，能在运行时根据不同语言使用者的需要，对同一个页面能够同时支持多种语言来做展示。

支持：

1. 在会话中存储国际化标识
2. 框架界面和 UI 组件国际化
3. 业务界面和 UI 组件国际化
4. 异常信息和接口调用国际化

目前已支持简体中文、繁体中文、英文，关于国际化的详细说明，<a href="#/doc/use/i18n">[ 请看这里 ]</a>。



## 自定义点击事件

Touch UI 使用了 tap 事件（类似 fastclick）替代了原有的 click 点击事件，于是，我们可以：

1. 解决部分触屏设备点击延时的问题。
2. 自由控制延时时间，加入触点按下样式、按下后滑出消除样式。
3. 在事件中挂载用户行为采集的方法。
